## Что сейчас видно

По логам backend-а запросы входа по email/паролю доходят до системы авторизации, но последний ответ был:

```text
Invalid login credentials
```

То есть кнопка входа, скорее всего, нажимается, но система не принимает пару email/пароль. Также есть отдельная ошибка старого токена в preview:

```text
Invalid Refresh Token: Refresh Token Not Found
```

Это похоже на устаревшую сохранённую сессию в браузере/preview и может создавать ощущение, что авторизация «зависла».

## Почему это выглядит как «почта и логин не работают»

В текущем коде есть несколько слабых мест:

1. После регистрации по email приложение сразу пишет «Аккаунт создан» и ведёт в `/app`, даже если email ещё нужно подтвердить. Если подтверждение включено, пользователь фактически ещё не вошёл, и его возвращает на логин.
2. Ошибка `Invalid login credentials` показывается как технический текст, без объяснения: неверный пароль, email не зарегистрирован, email не подтверждён или аккаунт был создан через Google.
3. Нет восстановления пароля, поэтому если пароль забыт или аккаунт создан другим способом, пользователь застревает.
4. Устаревший refresh-token в preview не очищается явно, из-за чего могут быть повторные неудачные попытки обновления сессии.

## План исправления

### 1. Исправить страницу регистрации

В `src/routes/register.tsx`:

- после `signUp()` проверять, вернулась ли активная сессия;
- если сессии нет, показывать понятное сообщение: «Проверьте почту и подтвердите регистрацию»;
- не переводить автоматически в `/app`, пока пользователь реально не авторизован;
- добавить русские сообщения об ошибках вместо технических.

### 2. Улучшить страницу входа

В `src/routes/login.tsx`:

- заменить `Invalid login credentials` на понятное сообщение на русском;
- подсказать варианты: проверить пароль, подтвердить email, использовать Google, если аккаунт создан через Google;
- не делать лишний переход в `/app`, если сессия ещё не установлена;
- добавить ссылку «Забыли пароль?».

### 3. Добавить восстановление пароля

Создать публичные страницы:

- `/forgot-password` — форма ввода email и отправка письма для сброса пароля;
- `/reset-password` — форма установки нового пароля после перехода из письма.

Технически будет использоваться встроенная авторизация Lovable Cloud:

```ts
supabase.auth.resetPasswordForEmail(email, {
  redirectTo: `${window.location.origin}/reset-password`,
})

supabase.auth.updateUser({ password })
```

### 4. Сделать auth-состояние устойчивее к старым токенам

В `src/lib/auth-context.tsx`:

- обрабатывать ошибку восстановления сессии;
- если локальная сессия битая/устаревшая, сбрасывать её и прекращать бесконечную загрузку;
- оставить корректный порядок инициализации: подписка на изменения авторизации + чтение текущей сессии.

### 5. Проверить поведение после правок

Проверить сценарии:

- вход с неправильным паролем показывает понятное сообщение;
- регистрация не притворяется успешным входом, если нужно подтверждение email;
- ссылка восстановления пароля доступна со страницы входа;
- старый/битый preview-токен не держит приложение в загрузке;
- вход через Google остаётся без изменений.

## Что не меняется

- База данных и таблицы не нужны.
- RLS и данные задач/планера не трогаются.
- Google-вход остаётся как есть.
- Подтверждение email не отключаю: это безопаснее и правильно для обычной регистрации.
