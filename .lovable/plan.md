## Раздел «Проекты» — план

Добавить четвёртую вкладку «Проекты» рядом с Месяц / Неделя / День. Внутри — горизонтальный ряд колонок (kanban-стиль). Каждая колонка = проект: сверху редактируемое название, ниже чек-лист пунктов. Пункты можно отмечать (зачёркивать), снимать отметку, удалять, добавлять новые. У каждого пункта — необязательная дата. Если дата проставлена, пункт автоматически появляется в Дне / Неделе / Месяце на эту дату.

### UI

- Маршрут: `/app/projects`.
- В шапке `src/routes/app.tsx` добавить таб «Проекты» → `/app/projects`.
- Страница:
  - Заголовок «Проекты» + кнопка «+ Новый проект» (создаёт колонку с дефолтным названием, фокус на инпут названия).
  - Колонки в горизонтальном скролле (`overflow-x-auto`, flex), фиксированная ширина ~280–320px, стиль `card-soft`.
  - В колонке: инпут названия (autosave по blur), список пунктов, инпут «+ добавить пункт» снизу.
  - Пункт: чекбокс • текст (inline-edit) • кнопка-«календарик» (Popover c shadcn Calendar) для даты • крестик удаления.
  - Если у пункта стоит дата — рядом с текстом маленький бейдж `15 мая` (кликабельный, открывает тот же поповер; крестик в поповере очищает дату).
  - Зачёркнутые пункты — `line-through text-muted-foreground`.
  - Удаление проекта — иконка-меню в шапке колонки с подтверждением.

### Данные (миграция)

Две новые таблицы:

- `projects`
  - `id uuid pk`, `user_id uuid not null`, `title text not null default ''`, `sort_order int not null default 0`, `created_at`, `updated_at`.
  - RLS: владелец видит/правит/удаляет только своё (как у `goals_monthly`).
- `project_items`
  - `id uuid pk`, `project_id uuid not null references projects(id) on delete cascade`, `user_id uuid not null`, `title text not null default ''`, `is_done bool not null default false`, `due_date date null`, `sort_order int not null default 0`, `created_at`, `updated_at`.
  - Индекс по `(user_id, due_date)` для быстрых выборок в календарях.
  - RLS аналогично — по `user_id`.
- Триггер `update_updated_at_column` на обе таблицы.

Существующие таблицы (`tasks`, `notes`, `astro_events`, `goals_monthly`) не трогаем.

### Связка с календарями (Месяц / Неделя / День)

Принцип: пункты с проставленной `due_date` показываются в календарных представлениях как задачи, помеченные иконкой/префиксом проекта. Источник правды — `project_items`, ничего не дублируем в `tasks`.

- `src/routes/app.day.tsx` — добавить параллельный запрос `project_items` с `due_date = date` (с join названия проекта через отдельный запрос `projects`). Объединить со списком `tasks` в блоке «Задачи»: пункт проекта отображается с маленьким бейджем названия проекта; чекбокс → `update is_done`; редактирование текста и удаление вызывают `project_items`, а не `tasks`.
- `src/routes/app.week.plan.tsx` — аналогично: дополнительный запрос `project_items` по диапазону недели, ячейки без `time_slot` (все проектные пункты идут без слота — рендерим в первой строке «весь день» или поверх первой ячейки 8:00; решение в плане: добавить отдельную строку «весь день» сверху таблицы, до часов).
- `src/routes/app.month.overview.tsx` — добавить проектные пункты в счётчик/превью задач месяца (как обычные задачи).
- Везде, где сейчас отображаются задачи, проектные пункты идут с подписью названия проекта мелким шрифтом, чтобы было понятно, откуда они.

### Технические детали

- Файлы:
  - новый: `src/routes/app.projects.tsx` (одна страница, без вложенных табов).
  - правки: `src/routes/app.tsx` (таб), `src/routes/app.day.tsx`, `src/routes/app.week.plan.tsx`, `src/routes/app.month.overview.tsx` (читать `project_items`).
- Сортировка проектов и пунктов — по `sort_order`. Новый объект получает `max(sort_order)+1` (как уже сделано в задачах Дня), без `Date.now()` (помним про прошлое переполнение `integer`).
- Дата-пикер — shadcn `Calendar` в `Popover` с `pointer-events-auto`.
- Все мутации идут через `supabase` browser-клиент, RLS обеспечивает безопасность.
- После создания миграции типы Supabase обновятся автоматически.

### Что не меняется

- Авторизация, существующие RLS, схема `tasks` / `notes` / `astro_events` / `goals_monthly`.
- Логика недели по часам, заметки, цели месяца, транзиты.

### Проверка после реализации

1. Зайти в «Проекты» → создать проект «Сайт» → добавить пункты «Дизайн», «Контент», поставить «Контенту» дату 25 мая.
2. Перейти в День 25 мая — пункт «Контент» появляется в задачах с пометкой «Сайт».
3. Отметить пункт в Дне — в Проектах он тоже становится зачёркнутым.
4. Убрать дату — пункт пропадает из Дня, остаётся в проекте.
5. Удалить проект — все его пункты исчезают из календарей (cascade).
