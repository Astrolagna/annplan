## Раздел «Контент-план»

Новая пятая вкладка рядом с Месяц / Неделя / День / Проекты. Календарь-сетка на текущий месяц. В каждой ячейке — кнопка «+», открывает модальное окно для записи постов на эту дату. Один пост = текст + теги соцсетей (мультивыбор). Посты появляются в общем месячном календаре кратко (иконки соцсетей + начало текста), а в Дне и Неделе — полностью.

### UI

- Маршрут: `/app/content`. Вкладка в `src/routes/app.tsx`.
- Сетка месяца как в `app.month.overview.tsx` (7 колонок, заголовки дней недели), кнопки переключения месяцев.
- Ячейка дня:
  - Число сверху.
  - Список постов (иконки выбранных соцсетей + первые ~30 символов).
  - Кнопка «+» открывает `Dialog` для этой даты.
- Диалог «Посты на N мая»:
  - Список существующих постов на дату (каждый — textarea + чипы соцсетей + удалить).
  - Кнопка «+ Добавить пост».
  - Внутри поста: `Textarea` (autosave по blur), ряд переключаемых чипов: Telegram, Instagram, VK, YouTube, TikTok, X, Threads, Facebook, LinkedIn (мультивыбор через массив).
  - Закрытие диалога — autosave всех изменённых.

### Данные (миграция)

Новая таблица `content_posts`:
- `id uuid pk`, `user_id uuid not null`, `date date not null`, `content text not null default ''`, `socials text[] not null default '{}'`, `sort_order int not null default 0`, `created_at`, `updated_at`.
- RLS по `user_id` (как `notes`/`tasks`).
- Индекс `(user_id, date)`.
- Триггер `update_updated_at_column`.

Список соцсетей хранится в коде как константа (label + ключ + иконка из `lucide-react` или эмодзи) — без отдельной таблицы.

### Связка с календарями

- **Месяц (`app.month.overview.tsx`)**: добавить запрос `content_posts` по диапазону месяца. В ячейке дня под существующими элементами — компактный блок: ряд иконок соцсетей + первые символы текста, до 2 строк.
- **Неделя (`app.week.plan.tsx`)**: запрос по диапазону недели. Отдельная строка «контент» сверху (рядом с проектной/всё-день строкой) — полный текст поста + чипы соцсетей.
- **День (`app.day.tsx`)**: запрос `content_posts` по дате. Новый блок «Контент-план» (рядом/под «Задачи»): полный текст каждого поста (textarea read-only или editable inline) + чипы соцсетей. Редактирование/удаление здесь же синхронизирует через ту же таблицу.

Принцип «источник правды один» — посты только в `content_posts`, нигде не дублируются.

### Технические детали

- Новый файл: `src/routes/app.content.tsx`.
- Правки: `src/routes/app.tsx` (вкладка), `src/routes/app.month.overview.tsx`, `src/routes/app.week.plan.tsx`, `src/routes/app.day.tsx`.
- `socials` — `text[]` в Postgres, в TS — `string[]`. Тогглинг через `socials.includes(key) ? filter : [...socials, key]`.
- Константа соцсетей — отдельный модуль `src/lib/socials.ts` (key, label, цвет/иконка), переиспользуется во всех вьюшках.
- Сортировка постов в дне — по `sort_order`, новый получает `max+1`.
- Все мутации — браузерный supabase-клиент, RLS защищает.

### Что не меняется

- Авторизация, существующие таблицы (`tasks`, `notes`, `astro_events`, `goals_monthly`, `projects`, `project_items`), их RLS и UI логика.
- Логика недели по часам, проекты, заметки, цели месяца, транзиты.

### Проверка после реализации

1. Открыть «Контент-план» → на сегодня нажать «+» → написать «Анонс марафона» → выбрать Telegram + Instagram → закрыть.
2. Месяц — в ячейке сегодняшнего дня появились иконки TG/IG и начало текста.
3. Неделя — в строке «контент» на сегодня полный текст и иконки.
4. День — в блоке «Контент-план» полный текст, чипы соцсетей, можно править.
5. Удалить пост в Дне — исчезает во всех представлениях.
